# M3E は LLM のワークベンチ

最終更新: 2026-11-18

M3E は表示の道具ではなく、LLM が node と edge を直接読み書きする作業台である。この文書は、そこから導かれる思想を定める。

## 1. 中心の命題

**自然言語の曖昧さは構造に落とす。内容の解釈は agent が行い、形の検査と確定はアプリが行う。**

LLM が自然言語だけを読んで推論すると、否定のネストや但し書きの扱いが揺れる。同じ意味を構造として渡せば、LLM の仕事は「文の解釈」から「構造の評価」に変わり、規則が一定になる。

一方で、構造を作るために人が細かな操作を重ねるのでは負担が大きい。構造を作る操作は agent に頼めば済むので、構造は硬くしてよく、後から変えることも軽く扱える。

## 2. 役割の分担

| 担い手 | 行うこと |
|---|---|
| agent（AI agent と human） | 内容を読み、構造へ写す。たとえば本文から期限を読み取る、否定を反転として置く |
| アプリ | 形と不変条件を検査し、確定する。内容の意味は判断しない |
| human | 採否を確定する（[Principle.md](./Principle.md) 5「AI は提案、人間が確定」） |

## 3. 否定は構造で持つ（極性）

「A ではない」「NOT A」「A の否定」のような否定の書き方は揃わない。これを Deep の帯域に持ち込むと負債になる。そこで否定は文ではなく構造で表す。

- parent edge が「保つ（preserve）」か「反転する（invert）」かを持つ。これが正本である。
- node の有効な極性（正か負か）は、root からその node までの主木の経路上で、反転の回数の偶奇で決まる。これは導出値で、キャッシュとして持つ。
- 例外の入れ子も同じ規則で書ける。「a, b, c はだめ（ただし c2 はよい）, d もだめ」は、その親への parent edge を反転し、c2 への parent edge でもう一度反転すればよい。
- 有効な極性は主木の経路だけで決める。alias や relation edge の経路は数えない。
- 表示では、負の node にだけ `[NOT]` を出す。

LLM は node・parent edge の反転・経路をそのまま読めるので、否定の判断は経路上の偶奇の評価になる。

## 4. 種別は軽く変える

- node の種別を立てるのは、details の形か構造上の拘束が他と違うときだけにする。分類の違いだけなら attribute にする。
- 種別の変更は、node の ID・parent edge・relation edge・alias からの参照・attribute を保ったまま details だけを作り替える、一つの操作として扱う。
- 行って戻っても情報を落とさない。新しい種別が持てない欄は捨てずに attribute へ移し、元の種別に戻すときに読み戻す。
- 本文から新しい種別の欄を読み取るのは agent の仕事である。アプリは読み取られた値が形に合うかだけを検査する。読み取れない欄は空のままでよい。
- 例: 「11/18 外出」というプレーンな node を task にするとき、agent が「期限 2026-11-18、状態 open」を読み取り、アプリが形を検査して確定する。

種別の変更が軽ければ、「後から task になるかもしれない」という理由で種別を避ける必要はない。形のはっきりした種別を使い、必要になったときに変える。

## 5. task とチケットの運用

- task は種別の一つとして持つ。状態・担当・期限・優先度・完了条件のような決まった形の欄を持つ。
- どの node も、種別の変更で task になれる。task をやめるときも同じ操作で戻せる。
- 「これが終わるまで始められない」という待ち合わせは、relation edge として表す。
- 担当や状態で task を引く見方（チケットの一覧）は、問い合わせと Surface View で作る。map とは別の管理表を持たない。
- [Engine.md](./Engine.md) との関係: 未完了の task は、まだ選ばれていない選択肢である。それが多い scope は温度が高く、完了や取り下げが進むことは冷却と圧縮にあたる。

## 6. 決まっていないこと

- task の欄の正確な組と値の範囲、担当の参照先（アカウントか agent の node か）
- 種別の変更で行き来できる組み合わせ。alias は子を持てず参照先が必須なので、行き来の対象から外す案がある
- alias の有効な極性を、alias が置かれた位置の経路だけで決めるか、参照先の極性も加えるか
- 極性を Glossary の語として登録する時期
