# Disperse 共通力学の通常 Beta 接続

2026-10-20。ユーザー指示: Labだけで終わらせず、通常Disperseで操作・保存・性能まで検証する。
本番は通常 Beta（4173）の既存 Viewer。Final チャネルの公開操作は含まない。
関連会話: [OT力学の比較・Lab構築](codex://threads/01a0a47f-b5ea-7961-b5c9-6c8679c3892a)。

## 要件・範囲

- グラフ・寸法変更とパラメータ変更で現在位置から再加熱する。
- 安定時に停止する。計算上限停止・制約未解消を安定と偽らない。
- ドラッグ中だけ対象を固定し、他ノードの力学を止めない。解放・cancel・capture喪失で解除する。
- 親子は包含、GraphLinkだけがばね。Lab・NETWORK・通常Disperseは同じ共有エンジンを使う。
- D3 quadtreeを用いたBarnes–Hut近似。OTの距離二乗反比例・距離上限は維持する（d3-forceの異なる力の式を無条件採用しない）。
- RBushで矩形衝突候補を絞り、包含・固定・間隔の既存assertionを保つ。
- 計算途中の位置は一時状態。停止・明示一時停止・View切替で既存surface座標へ確定し保存する。Undo/Redoと再読込を検証する。
- 専用背景の上書きを除き共通テーマへ従う。調整Panel全面再設計・新保存形式は範囲外。

## 変更前に固定する検証条件

- 既存OT力学試験の非重複・包含・pin・collapse・停止条件を維持する。
- 近似と厳密計算を独立比較する。密度・完全同座標・固定ノードを含む。
- 400/2000ノードで力学stepと描画を別計測。目標:400のstep p95 <=16ms、2000のstep p95 <=50ms（端末依存の測定結果を併記）。未達は未達と報告し基準を下げない。
- 通常Viewerでグラフ変更→再加熱、ドラッグ中固定→解放、停止、文字編集・折り畳み・scope切替・Undo/Redo・保存再読込を確認する。
- 一時データのheadless試験と、統合後の通常Betaで元症状の読取確認を分ける。個人mapにfixtureを書かない。
- 本流統合・push・通常Beta build後、配信と表示を確認する。見た目と動作感の最終確認資料をまとめる。

## 状態

以下は通常Betaへ反映する実装と、統合前の検証記録。Lab既存の100ノード検証や2000ノード描画検証を、新しい力学の合格証拠へ流用しない。

## 実装と検証の記録（2026-10-20）

- `DisperseForceController` が一時座標と再加熱・停止・ドラッグを仲介し、Lab / NETWORK と同じ `ot_force` を使う。Viewer独自の全ペア力学とTree状seedを削除。既存の親子ガイドの描画は維持するが、ばねには使わない。
- D3 quadtree に載せる計算は既存OTの距離二乗反比例・300単位の上限を維持。RBushで矩形候補を抽出し、停止時の密な接触連鎖は既存WebCola/VPSCで解消する。WebColaの中心座標比較における同値を微小量で決定論的に分け、別矩形が候補木から欠落するケースを回避した。
- 標準パネルへ既存collapse操作を接続。背景とラベルのDisperse専用暗色上書きを除去し、共通テーマへ従う。
- 一時SQLite workspaceと通常Viewer serverによるheadless試験: ドラッグ中の固定、解放、パラメータ反映、停止、保存・再読込、編集、追加、折り畳み、Undo/Redo、scope出入。
- 力学単体の直近測定: 400ノード p95 約2.9ms、2000ノード p95 約18.8ms。いずれも斥力・衝突を含み、描画を含まない。事前条件16ms/50msを変更していない。負荷同時実行時に400ノード20.9msの失敗があり、重複した幾何計算を削減して再検証した。
- 400ノードの通常Viewer: 240stepで計算上限停止・重なり0、描画を含むframe p95 約33–38ms。収束したという判定ではない。
- ユーザー指定の「状況」scopeをMCPで読み取り、419ノード/112グループを隔離環境へ再現。重なり0・計算上限停止・WebGL active・page error0。描画込みp95 約64ms。動作中の描画には改善余地があり、60fpsを達成したとは主張しない。個人mapには試験データを書いていない。
- 試験中に残った重なりは条件を緩めず修正。修正前の診断runは最終検証から区別する。
- 既存保存座標は再読込時に保持する。Reflowは現在位置から再加熱し、毎回Tree状へ置き直さない。新規ノードの初期位置は旧Tree状seed以前の放射状seedを利用する。

実機WindowsとFinalチャネルの公開は対象外。通常Beta配信の結果はローカルの検証パケットに保持する。

## 計算中のWebGL経路の追加検証

- 連続renderがWebGL切替のrequestAnimationFrameを毎回cancelしていた。静止後のWebGL activeだけではAnimate中のGPU経路の証拠にならない。切替予約をcoalesceし、動作中の位置更新回数を診断値で検証するよう変更した。
- 構造・文字・スタイルが変わらないフレームは、既存WebGL paintの行列・境界・親子ガイド・包含枠だけを更新する。ガイド端点は通常SVGと同じ円境界関数を共有する。GraphLinkの曲線・ラベルがある場合は従来の完全描画へ戻り、その見た目を近似で置換しない。
- 419ノード/112グループの元scope再現: 動作中の位置更新238回、描画込みframe p95 約36ms、240stepで計算上限停止、重なり0、WebGL active、page error0。400ノードでは約14ms。前節の64msは位置更新最適化前の診断値であり最終値ではない。
- 最後の制約解消で生じた移動もmaxMove/有限値検査へ含める。大きな補正を「安定」と誤判定しない。
- 停止直後のカメラfitを待たないブラウザー試験にクリック競合があった。停止後の描画完了を待ってから入力するよう修正した。停止閾値・性能目標・幾何assertionは変更していない。
- 既存SVG DOMを座標源とするscatter_surface試験は、標準WebGL時に非表示SVGのboundingBoxを取得できず1件失敗した。試験assertionを変更していない。明示的なSVG fallback診断では同じ2件が成功。通常WebGLのドラッグ・ノード追加・GraphLink追加は別途、実サーバー/一時SQLiteのUI操作で検証する。

Barnes–Hutは一般にO(N log N)であり、完全同座標や密な包含制約での最悪O(N)を保証しない。2000ノードの描画込み60fps、GraphLink多数時の位置専用経路、Windows実機は未検証。

- 元scopeの全体fitが旧15%下限で切れたため、通常Disperseだけは実ジオメトリに応じて縮小下限を下げる。他surfaceのzoom方針は維持する。
