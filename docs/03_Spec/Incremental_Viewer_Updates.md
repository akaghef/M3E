# Viewer の編集確定時の差分更新

## 要件と境界

- RQ1: 文字変更時は対象ノードの文字寸法・ボックス寸法を必ず再計測する。寸法変更による配置の波及を省略しない。
- RQ2: 未変更ノードの寸法・SVG、未変更の枝サイズ、影響領域外のWebGLタイルを再利用する。
- RQ3: Enter / Tab の「確定→追加→編集開始」は1回の表示更新とする。確定と追加のUndo履歴は従来どおり別々に保持する。編集開始をGPUフレーム到着に依存させない。
- RQ4: 差分計算の配置・edge形状・文字表示は従来の全体計算と一致させる。保存形式、Command、scope、alias、GraphLink、キー仕様は変更しない。

## 実装

ラベル確定とノード追加だけが差分更新を要求する。その他の変更、Undo / Redo、表示設定変更、外部state受信は既存の全更新経路でキャッシュを無効化する。

文字計測はnode IDごとに入力ラベル・root判定・LaTeX判定・葉判定・文字配置設定を比較する。Treeの枝サイズは各子の計算結果と自分の幅または高さを比較し、未変更なら再利用する。祖先に到達しても子の枝サイズが変わらなければ、その先の枝サイズ再計算は不要。

段揃え、左右／上下方向、兄弟の順序を含む配置の走査は既存アルゴリズムを維持する。ノード描画と親子edgeの経路生成は入力ごとにキャッシュする。SVGは安定したノード／edge単位のgroupを保持し、変化したfragmentだけ置換する。WebGLのSVG計測・経路サンプリングも未変更要素を再利用する。タイルは変更前後のpaint boundsに重なる領域だけ無効化する。重なり順序変更も無効化対象。

## 残る全体処理

完全な O(変更数) 実装ではない。配置の走査・段ごとの最大寸法集計・描画入力比較・空間索引構築・SVG全体bounds確認は残る。Undo全state複製、モデル整合処理、別タブ同期も既存経路を維持する。Treeでは実際に全体配置が動く編集もある。処理回数の削減と体感性能の判定は区別する。

## テスト観点

- 6方向 × packed/alignedについて、寸法変更・追加・削除・並べ替え後の差分計算と全体計算の一致。
- 307ノードの隔離fixtureで、変更ラベルだけの計測・無関係DOM保持・ボックス拡張・接続線とhitbox更新。
- SVG / WebGL双方でEnter / Tabの表示更新回数、次エディタへのfocus、従来のUndo単位を確認する。
- 既存キー操作回帰試験。個人workspaceのデータは変更しない。性能の時間計測はこの確認に含めない。

正常系は文字確定・子／兄弟追加、境界は複数行の拡張／縮小・方向変更・削除・重なり順序変更、失敗系はWebGL非対応時にもSVG側の更新と編集操作を維持すること。全更新経路へ切り替わった際は計測キャッシュを破棄し、古い寸法を使わない。
