# Codex / Claude Instruction Sync Protocol

## Goal

Codex and Claude must see compatible M3E rules while preserving their different roles:

- Claude = Director.
- Codex = worker.

## Canonical Operating Sources

Claude-facing Director contract:

```text
CLAUDE.md
docs/06_Operations/Director_Playbook.md
```

Shared operating protocols:

```text
AGENTS.md
docs/protocols/
docs/06_Operations/AI_Instruction_Routing.md
docs/06_Operations/Worktree_Separation_Rules.md
```

Skill mirrors, when present, are compatibility surfaces:

```text
.codex/skills/
.claude/skills/
.agents/skills/
```

## Rules

- `docs/06_Operations/Worktree_Separation_Rules.md` owns integration and delivery for both tools. PRs are optional; Codex can deliver its authorized task through normal Beta verification.

- Do not reintroduce Claude implementation workers.
- Protocol changes that alter Codex behavior must update any relevant skill source or mirror in the same delivery.
- Generated mirrors must contain a generated header when the sync tool manages them.
- If a mirror conflicts with `CLAUDE.md` or `Director_Playbook.md`, the canonical Director sources win for Claude behavior.

## Scoped delivery-skill sync

Delivery skills are canonical under `agent_instructions/skills_canonical/`. After pulling changes, update local mirrors with:

```bash
node tools/sync_agent_instructions.mjs --write --skill=m3e-worker --skill=devM3E --skill=pr-beta --skill=pr-review --skill=beta-converse --skill=daily-sync --skill=nightly-autopilot --skill=setrole --skill=canvas-protocol
node scripts/ops/check-delivery-policy.mjs
```

`--skill=<name>` limits changes to the named canonical skill. `--mirror=.claude/skills` and `--mirror=.agents/skills` limit checks to tracked mirrors in CI; local `.codex` mirrors are also generated by the default write command. Unrelated broken legacy symlinks must not cause an ad hoc mirror copy.
