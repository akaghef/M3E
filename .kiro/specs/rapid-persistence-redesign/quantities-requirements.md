# 物理量と拡張の土台の要件（案）

- 本書の ID（R は要件、Q は akaghef に決めてもらう問い）は、本書を書いた会話の中の住所である。
- 「確定」は akaghef の発言に根拠があるもの、「仮」は推奨を仮に採ったもので、承認待ち。

## 1. 目的

agent に map の運用（整理、更新の提案、優先度付け）を任せるために、agent が推論に使える客観的な量を map に持たせる。主観的な評価（重要度、更新したさ）は直接測らず、意図は目標として明示させ、測れる量との差で扱う。

## 2. 量の共通の契約

各量について、意味・定義の版・対象範囲・パラメータ・基準にした確定の位置・評価時刻・欠測の有無を識別できる。観測した事実、推定、目標を区別する。未観測を 0 と返さない。

## 3. 要件

### 3.1 計測と履歴

| ID | 初版 | 要件 | 受入条件 |
|---|---|---|---|
| R1 | 必須 | 2 節の共通の契約を満たす | 定義や観測範囲が違う値を、同じ意味の値として返さない。未観測を 0 と返さない |
| R2 | 必須 | 書かれる頻度と、確定に採用した出所を、保証した期間と粒度で再現するための出来事を保持する（仮） | 圧縮なし、途中で圧縮、圧縮後に全キャッシュを捨てる、の各経路で、同じ定義・評価時刻の結果が一致する。参照した版の特定と、その版の本文の復元は別の保証とする |
| R3 | 必須 | 圧縮で journal を消す前に、必要な履歴が欠けずに保存されている。復元に使う一式にその履歴を含める（仮） | journal への追記・履歴の保存・圧縮の各境界で異常終了しても、確定済みの履歴を失わない |
| R4 | 必須 | node の書かれる頻度は、node か自身の details に実際の差分を与えた確定を、node ごとに 1 件と数える。減衰には確定時刻を使う（仮） | node と details を同時に変えても 1 件。再送・拒否・作り直し・`rev` だけの差分では増えない。計算で求まる値だけが変わった子孫には足さない |
| R5 | 必須 | 内容の変更と、確認の申告を、別の出来事として保存する。確認は、対象とした内容の版に結び付ける（仮） | 内容を変えない確認も圧縮後に残る。v1 を読んだ後に v2 が作られても、v1 の確認を v2 の確認とみなさない |
| R6 | scope の書かれる頻度を出すとき必須 | 出来事を、当時の所属先に計上する（仮） | node を S から T へ移しても、S で起きた出来事を T へ付け替えない。初版で node の量だけを出すなら延期できる |

### 3.2 目標・足跡・出所

| ID | 初版 | 要件 | 受入条件 |
|---|---|---|---|
| R7 | 必須 | node ごとに更新の目標を一つ持ち、間隔と充足条件（内容の変更 / 確認 / どちらでも）を指定できる（仮。Q2） | 内容の変更を求める目標は、確認だけでは満たされない。未設定・休止・正の間隔を区別する |
| R8 | 必須 | 遅れ具合を、目標の版・最後の対象の出来事・評価時刻と対応させて返す（仮） | 目標を作る・変える・休止するだけでは、内容の変更や確認の時刻は進まない。古い目標で計算した値を、新しい目標の値として返さない。基準の出来事が不明なら、遅れ具合も不明 |
| R9 | 必須 | 出所の自動の候補は「返したことを観測した」候補として、明示の出典は申告として記録する。実際の取得元と、取得した版を持つ（仮） | 再送や復元で候補を取り直さない。alias を通して本文を取ったとき、alias の場所だけを取得元にしない |
| R10 | 必須 | 出所を保持することと、確定を見る人へ公開することを分け、公開の方針を適用する（Q3） | 同じ map というだけで、閲覧の行動を公開しない。共有の範囲を後で変えたときも同じ方針を当てる |
| R11 | 必須 | 出所の 100 件の上限について、順序を決める: 採用してよい候補を決める → 版を含めて重複を除く → 明示の出典を優先 → 100 件に切る（仮） | 切ったときは「不完全」とする。非公開の候補が増えても、公開する一覧と件数は変わらない |
| R12 | 必須 | 足跡は、届いた端末の分を合算し、観測期間・対象の端末・欠測を識別できる（仮） | 同じ集計を 2 回受けても倍にならない。未接続や記録の喪失を「読まれていない」と扱わない |
| R13 | 必須 | 参照について、今ある参照の数と、参照が作られた回数を区別する。関係の型・向き・作った主体を識別する | 作る → 消す → 作る、で今ある数は 1、作られた回数は 2。`m3e:blocks` を作ったことを、読んだことや支持と同一視しない |

### 3.3 構造・拡張・運用

| ID | 初版 | 要件 | 受入条件 |
|---|---|---|---|
| R14 | 必須 | 体積は、面への構造上の所属から数え、返す構造と同じ確定の位置に揃える（仮） | 折りたたみ・画面の移動・遅延読み込みで変わらない |
| R15 | 必須 | 極性は、限定した継承の符号として、map の root を基準に計算する。alias は置かれた位置の符号を持ち、参照先の符号は別に取れる（確定） | scope だけを開いても、同じ node の符号が変わらない。一般の論理式の否定までは保証しない |
| R16 | 必須 | 拡張の付与・解除を一つの操作で行い、必須の欄が揃うまで有効にしない。解除した値は残し、有効な拡張とは区別する（仮） | 必須の欄が足りなければ、有効にできたとは返さない |
| R17 | 必須 | 拡張は、適用した時点の定義の版に固定し、新しい版への移行は明示の操作にする。知らない定義と値も残す（仮） | 定義の v2 を足しても、v1 で適用した値を読み替えない |
| R18 | 必須 | 拡張の名前は、名前空間と定義の版で識別し、同じ名前で定義が違うものは衝突とする。旧い名前の対応規則を持つ（仮） | `misc:` も衝突の検査の対象。旧い `consist-of`・`detail` を一貫して解決できる |
| R19 | 必須 | 本文と、本文から取り出した欄のどちらを運用に使うかを決め、取り出した元の版を追える（仮） | 本文だけを変えた後、古い欄を「今の本文から取り出した」と扱わない |
| R20 | 必須 | agent に任せる範囲と、別の権限（目標の変更、task の解除、定義の変更）を、実際に起きる変更に対して検査する（Q4） | 汎用の attribute の更新、一括の変更、取り込み、Undo でも、別の権限を回り込めない |
| R21 | 初版では任意。出すときは必須 | 温度は、選択肢・確率の出所・正規化を定めた選択問題だけに出す（仮） | それ以外は「未定義」。全 scope に自動で集めない |
| R22 | 必須。時間の合格値は Q5 | 規模と同時の負荷を定めて、整合・応答時間・統計の遅れを検証する（仮） | 100 万 node、面の大きさは通常 10・最大約 1,100、十数の同時読み込みで検証する。祖先の反転、大きな変更、再起動の直後も含める |

## 4. 対話で分かったこと

- **圧縮すると、書かれる頻度を作り直せなくなる。** 確定の表は、どの確定がどの node に触れたかを持たない。「確定ごとに、差分を与えた node・details の一覧を、圧縮で消さない索引に残す」案で、R4 の頻度は作り直せる。ただし、内容の変更と目標の変更の区別、確認の申告、当時の所属、出所は、ID の一覧からは戻せない。それらは出来事の種類として残す必要がある。
- **索引は、journal を消した後は一次の履歴になる。** 「snapshot と journal だけから復元できる」（DB 仕様書 1 節）の約束を、この履歴を含める形に改める必要がある。圧縮の前に「どの確定まで履歴を保存したか」を確かめ、未保存の分を再生できる journal を先に消してはいけない。
- **`rev` では内容の最終更新を表せない。** 目標の attribute を変えるだけで `rev` が進む。遅れ具合の基準には、出来事の種類を区別した記録が要る。
- **「読んでから書いた」は、推論に使った証拠にならない。** 保証できるのは「書く前に、その session へこの版を返した」ことまで。
- **「同じ map の node だけを出所に残す」では、公開の許可の代わりにならない。** 内容を読めることと、他人が何を読んだかを知ってよいことは別。alias を通して別の map の本文を返した場合もある。
- **未完了の task を温度に使うと、向きが逆になる。** 完了が進むほどエントロピーが上がる。
- **極性の偶奇で表せるのは、禁止が下へ受け継がれる形だけ。** 「A と B の両方が成り立つわけではない」は、子へ分けると意味が変わる。
- **量を良く見せる操作に注意する。** 一つの修正を 10 回の Command に分ける、目標の間隔を延ばして遅れ具合を下げる、自分で作った参照を自分でたどる、未処理の task を子 scope へ移して体積を減らす、など。量は成果の評価に使わず、目的の達成は別に評価する。

### 容量の試算（実測ではなく、仮定した大きさによる計算）

確定 1 日 3,000 件のとき、確定ごとに差分を与えた node の一覧を残す場合の、1 年あたりの増加:

| 確定 1 件あたりの平均の対象数 | 1 年あたり |
|---:|---:|
| 1 | 約 0.21 GB |
| 10 | 約 0.84 GB |
| 100 | 約 7.15 GB |

- 出所を平均 10 件残すと、約 1.40 GB / 年が加わる。
- 効くのは、静的な node の総数ではなく、確定が触れる対象の合計である。大きな取り込みや削除の頻度が要る。
- 祖先の反転で子孫の有効な極性が変わっても、それを実際の差分の一覧に足さない（足すと、意味と容量の両方が変わる）。
- 過去の本文まで残すのは別の判断（平均 10 件 × 10 KB を毎回残すと、約 110 GB / 年）。

## 5. akaghef に決めてもらう問い

- **Q1 圧縮後の履歴をどこまで再現するか**: 全期間の出来事と出所の参照を持つ / 過去の本文と構造まで持つ / 期間を決めて持つ。推奨は「全期間の出来事と出所の参照を持ち、過去の本文の復元は別の要件にする」。
- **Q2 更新の目標**: 一つの目標に充足条件を持たせる / 内容の変更と確認に別々の目標 / 初版は内容の変更だけ。推奨は「一つの目標 ＋ 充足条件、既定は内容の変更」。
- **Q3 自動の出所の候補と足跡を誰に見せるか**: map を見る全員 / 共有の側には明示の出典だけ、自動の候補と個人の足跡は本人と任された agent だけ / 両方とも本人と任された agent だけ。推奨は 2 番目。
- **Q4 別の権限にする三つ（目標の変更、task の解除、定義の変更）を agent にどこまで任せるか**: 全部 human / 目標の変更だけを範囲付きで任せる / 三つとも Role ごとに任せる。推奨は「目標の変更だけを、対象と許す間隔の範囲付きで任せる」。
- **Q5 応答時間と統計の遅れの合格値**: 推奨は「構造と統計で上限を分ける」。たたき台は、同時 16 の読み込みで、通常の面の p95 が 200 ms 以内、最大の面の p95 が 1 秒以内、統計の遅れは 60 秒以内（未測定・未承認）。
