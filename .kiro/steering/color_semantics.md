# 色の意味規約（binding steering）

> 色で状態を示す UI は本書を **honor 必須**。
> 2026-08-29 akaghef 決定: 「色に関しては規約を統一したいため、規約に追加してほしい」。
> **map 全体の規約であり、agent 固有ではない。** agent lifecycle state はこの規約の消費者のひとつ。

## 使う色（7色。これ以外を状態表現に使わない）

| 色 | 意味 | 判断基準 |
|---|---|---|
| **青** | **正常稼働** | 意図どおり動いている。人が見に行かなくてよい |
| **黄** | **判断待ち** | **人の入力・承認・選択を待って止まっている。人が動かないと進まない** |
| **オレンジ** | **停滞 / 要注意** | 止まっているが壊れてはいない。人を呼んではいないが進んでいない |
| **緑** | **完了** | 正常に終わった。もう動かない |
| **赤** | **異常** | 壊れた。失敗した。意図しない終わり方をした |
| **灰** | **アーカイブ** | 人が畳んだ。現役ではないが記録として残す |
| **白** | **未配色** | 色を決められない。未分類、または観測できず状態が確定しない |

## 拘束規則

1. **色数を増やさない。** 7色で表せない区別が要るなら、それは色ではなく**文字・形・線種**で表す。8色目を作らない。

2. **黄は人を呼ぶ色。乱用しない。** 「人が動かないと進まない」ときだけ黄にする。「人が見ておくとよい」程度はオレンジ。黄が画面に散ると Attention Routing（ADR_011 DC13）が機能しなくなる。

3. **白は「まだ決まっていない」であって「正常」ではない。** 観測できない・分類されていない状態を白にする。既定値として白を置くのは正しいが、白のまま放置される設計にしない。

4. **灰は人の操作の結果であり、機械が付ける色ではない。** アーカイブは人が畳んだという事実を表す。観測結果として自動的に灰にしてはならない（それは白かオレンジ）。

5. **色は状態の要約であり、状態そのものではない。** 細かい状態名は文字で出す。色は遠景・一覧・周辺視で「どれを見るべきか」を決めるためのもの。**色だけで状態を特定できる必要はない。**

6. **色覚多様性を前提にする。** 赤と緑を色だけで区別させない。形・位置・文字のいずれかを併用する。

## agent lifecycle state への割り当て

ADR_011 DC11 の10種を本規約の7色へ写像する。

| 色 | lifecycle state |
|---|---|
| 青 | `starting` / `thinking` / `tool-running` |
| 黄 | `awaiting-user` |
| オレンジ | `blocked` / `idle` |
| 緑 | `completed` |
| 赤 | `failed` / `disconnected` |
| 白 | `unobservable` |
| 灰 | （lifecycle state ではない。人が畳んだ node） |

補足:

- `unobservable` に **白**が当たるのは意味が一致する。観測できないから色を決められない。既定値としての白と、観測不能としての白は同じ意味になる。
- `disconnected` は**赤**。切断は意図しない終わり方であり、`completed`（緑）と区別する。ADR_011 DC5 が「正常終了・観測不能・切断を分ける」と定めた3者は、緑 / 白 / 赤 に分かれる。
- `idle` に**オレンジ**を当てるのは、prototype が長時間 `idle` を `gone` に落としていた欠陥（56時間 `IDLE` 表示）への対処でもある。止まっていることが色で見える。
- **灰は agent lifecycle には現れない。** アーカイブは人の操作なので、規則4のとおり機械が付けない。

## 適用

- 状態を色で示す UI（node、badge、リング、一覧、minimap）は本規約に従う。
- 実装は色名ではなく**意味名**（`normal` / `awaiting` / `stalled` / `done` / `error` / `archived` / `unset`）でトークン化し、色値は1箇所で解決する。テーマ差し替えと色覚配慮のため。
- 本規約と個別 spec が食い違った場合は**本規約が正**。spec を直す。
